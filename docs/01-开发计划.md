## 4. 开发流程规范

### 4.1 Git 提交规范

```
feat: 新增买花阶段 UI
fix: 修复同色系规则误匹配
docs: 更新组合规则数值表
chore: 调整项目配置
```

- 一个提交只做一件事；`main` 分支始终保持可运行状态。
- 提交前必须跑冒烟测试。

### 4.2 验证规范

```powershell
$godot = "$env:LOCALAPPDATA\Programs\Godot\godot_console.exe"
& $godot --headless --path "D:\yyy\flower" "res://tests/smoke_test.tscn"
```

新增核心系统必须同步扩展冒烟测试。

### 4.3 数值平衡流程

1. 所有花材 / 规则 / 事件均以 `.tres` 定义，改数值不碰代码；
2. 调整后在 `docs/` 记录平衡表变更（date、改了什么、为什么）；
3. 大规模调整前先做理论收益测算，避免「无敌公式」。

## 5. 风险与应对

| 风险 | 影响 | 应对 |
|------|------|------|
| 组合规则被穷举出最优解 | 决策退化为重复劳动 | 每日事件 / 流行趋势 / 随机花材池打破固定环境；规则数据化便于快速调整 |
| 内容量不足 | 5 小时内摸透全部组合 | 30+ 花材 × 多维规则，目标组合空间 > 10 万 |
| 平衡性失控 | 挫败感或无聊 | M1 起建立数值表格；内部测试迭代 |
| GodotSteam 版本兼容 | Steam 功能无法接入 | 锁定 Godot 4.7.2 + GodotSteam 4.22（官方已验证组合） |
| 节奏拖沓 | 每天像上班 | 每个阶段 ≤ 30 秒决策密度；营业动画可加速/跳过 |

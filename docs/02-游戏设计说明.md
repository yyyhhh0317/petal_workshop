# 游戏设计说明（GDD v0.2）

**项目**：Bloom & Bust —— 花店 Roguelite 策略经营游戏
**设计目标**：把「静态解谜盒」变成「动态策略系统」——玩家研究的不是"哪个组合分最高"，而是"在我当前有限的资源下，如何做出最优决策"。

---

## 1. 设计支柱

| 支柱 | 说明 |
|------|------|
| **组合策略** | 花材之间的增值 / 贬值规则构成核心策略深度，是"发现隐藏公式并验证"的乐趣来源 |
| **Roguelite 结构** | 每局随机开局，失败积累元进度，永不归零；把"经营"变成"生存" |
| **数据驱动** | 花材、规则、事件全部以数据资源定义，数值调整不碰代码 |
| **轻量经营** | 逻辑简单，聚焦决策而非操作复杂度；每阶段 ≤ 30 秒决策密度 |

**目标体验**：易懂难精。基础规则（同色系增值）开局即明；隐藏规则（传说组合、禁忌搭配）随进度逐步发现，制造持续的"啊哈！"时刻。

## 2. 核心循环

每一天严格按状态机推进：BUY -> ARRANGE -> DISPLAY -> BUSINESS -> SETTLEMENT。

1. **买花阶段（BUY）**：从当前周目的花材池进货，受资金约束。花材池每局随机（开局仅 3-5 种可见，随天数逐步解锁）。
2. **组合阶段（ARRANGE）**：把库存花材组合成花束（1 束 = 3-5 支花），系统实时预览组合价值与命中的规则。
3. **展示阶段（DISPLAY）**：把花束放进展示柜。位置影响价值：橱窗位 ×1.5（匹配流行趋势时更高）、中央展台、角落位各有不同效果。
4. **营业结算（BUSINESS -> SETTLEMENT）**：模拟营业——顾客到访、按偏好挑选花束、付款；结束后结算收支、检查胜负条件，进入次日。

## 3. 组合系统规格（核心）

### 3.1 花材维度

| 维度 | 取值示例 | 用途 |
|------|---------|------|
| 颜色标签 color_tags | red / white / yellow / warm / cool / filler… | 颜色协同、流行趋势匹配 |
| 种类 category | rose / lily / chrysanthemum / filler… | 类别协同、传说组合 |
| 稀有度 rarity | 1-5 | 基础价值倍率、解锁门槛 |
| 花语 description | 文本 | 文化质感、图鉴收集 |

### 3.2 规则类型与优先级

优先级从高到低（数字越大越先应用，乘法叠加）：

| 优先级 | 类型 | 说明 | 示例 |
|-------|------|------|------|
| 100 | 禁忌 TABOO | 特定组合直接贬值 | 百合+菊花 ×0.5（祭祀联想） |
| 20 | 传说 LEGENDARY | 稀有固定搭配大幅增值 | 玫瑰+满天星 ×2.0（"期待重逢"） |
| 10 | 类别协同 CATEGORY | 特定类别组合加成 | 花材全为 filler ×1.15 |
| 5 | 颜色协同 COLOR | 同色系增值 / 对比色减值（基础规则，开局即有） | 全束共享色系标签 ×1.1 |
| — | 位置加成 | 展示柜位置效果 | 橱窗位 ×1.5 |
| — | 当日流行 | 与当日流行标签匹配的整束加成 | 流行紫色 ×1.2 |

**计算流程**：最终价值 = 基础价值之和 × Π(命中规则的 value_multiplier) × 位置加成 × 流行加成（乘法叠加，四舍五入取整）。

### 3.3 骨架已实现的示例规则

| 规则 id | 类型 | 条件 | 倍率 |
|---------|------|------|------|
| taboo_lily_chrysanthemum | 禁忌 | 同时含百合+菊花 | ×0.5 |
| legendary_rose_babys_breath | 传说 | 同时含玫瑰+满天星 | ×2.0 |
| same_color | 颜色协同 | 所有花材共享色系标签 | ×1.1 |

### 3.4 规则字段（ComboRule）

id / display_name / rule_type / priority / value_multiplier / required_ids（必须全含）/ any_of_ids（至少其一）/ required_tags + min_matches / required_category / require_shared_tag（全束共享标签）/ is_taboo / description

规则以 .tres 定义，M3 阶段扩至 100+ 条。

## 4. Roguelite 结构

### 4.1 周目（Run）

- **目标**：在 N 天内还清债务 / 达到目标声望（默认 30 天，M2 引入剧本化目标）。
- **失败条件**：资金归零且无货可卖 / 连续 3 天亏损（M2 细化）。

### 4.2 随机化清单（全部由种子派生）

| 随机项 | 说明 |
|--------|------|
| 开局花材池 | 从已解锁花材中随机 3-5 种起步 |
| 每日事件 | 流行色、花市价格扰动、特殊顾客等 |
| 顾客 | 偏好、预算、耐心浮动 |

### 4.3 种子原则

- 同一种子 -> 完全相同的周目（可复现、可分享、可竞技）。
- 每日挑战 = 全球统一固定种子。

## 5. 元进度（Meta）

失败即积累，是本作解决"玩几天就玩到头"的核心：

| 类型 | 获取方式 | 效果 |
|------|---------|------|
| 花语图鉴 | 首次命中组合规则时记录 | 提供组合预览信息；收集乐趣 |
| 花材解锁 | 累计游戏进度 | 扩展可用花材池 |
| 技能点 | 每局结束按表现获得 | 初始资金+、展示位+1、进货折扣等 |
| 店铺声望 | 累计经营天数 | 解锁新顾客 / 新事件 / 新开局剧本 |
| 每日挑战记录 | 完成每日挑战 | 排行榜排名、特殊称号 |

**幅度控制**：永久升级保持 +5-15% 的微妙增幅（破坏性提升会摧毁技能驱动的核心体验）。

## 6. 内容规格（M3 目标）

| 内容 | 数量目标 |
|------|---------|
| 花材 | 30-50 种（花语 + 背景故事） |
| 组合规则 | 100+ 条（禁忌 / 传说 / 颜色 / 类别） |
| 随机事件 | 20+ 模板 |
| 顾客类型 | 10+ 种（忧郁的诗人、挑剔的贵妇……） |
| 理论组合空间 | > 10 万种 |

## 7. 数值初稿（M1 用）

| 项 | 初值 |
|----|------|
| 起始资金 | 500 |
| 花材基础价值 | 8-20（稀有度 1） |
| 进货成本 | 约为基础价值的 50% |
| 花束容量 | 3-5 支 |
| 目标天数 | 30 |
| 顾客预算 | 基础价值 × 1.5-3.0（受满意度影响） |

骨架示例花材：玫瑰（20/成本10）、百合（15/8）、菊花（15/8）、满天星（8/4）。

## 8. 每日挑战与无尽模式（M4+）

- **每日挑战**：固定种子 + 全球统一开局，排行榜比较收益；完成率控制在 65-75%。
- **无尽模式**：主线结束后自由经营，声望等级递增，顾客要求更刁钻、流行变化更快。

## 9. 平衡原则

1. 每个阶段存在 ≥ 2 个非平凡决策点；
2. 禁止"无视局面的万能配方"——任何规则都应被至少一种事件 / 局面克制；
3. 新花材的引入必须打破至少一个旧最优解；
4. 数值调整只改 .tres，并在文档中记录变更理由。
